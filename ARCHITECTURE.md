# Instiy — Architecture & Code Guide

A student marketplace built with Flutter, Supabase, and Cloudflare. This guide
documents how the codebase is organized, the key conventions, and the things you
must not break (cold-boot path, splash, deep links, secrets, payments).

---

## 1. Tech stack

| Concern            | Choice                                                        |
| ------------------ | ------------------------------------------------------------ |
| UI framework       | Flutter (Dart SDK ^3.12)                                      |
| Design system      | `shadcn_ui` (`ShadApp`, `ShadTheme`) + Material fallback     |
| State management    | Riverpod 3.x (ChangeNotifier hybrid + codegen)               |
| Backend / Auth     | Supabase (Postgres, GoTrue auth, Realtime)                    |
| Serverless         | Cloudflare Workers at `api.instiy.com` (`/functions/v1/...`)  |
| Media storage      | Cloudflare R2 (uploaded via the API proxy, not direct keys)  |
| Local cache        | Hive (`products_cache`) + SharedPreferences                  |
| Push               | Firebase Cloud Messaging + `flutter_local_notifications`      |
| Payments           | Paystack (SDK + Worker `paystack/*` endpoints)               |

---

## 2. Directory layout (`lib/`)

```
config/      App-wide constants (AppConfig) and theming (AppTheme).
models/      Plain Dart data classes with fromJson / toJson.
services/    Stateless, static-method classes that talk to Supabase / HTTP /
             platform plugins. No UI, no state.
providers/   Riverpod providers + ChangeNotifier state holders. UI-facing state.
repositories ProductRepository — cache-first stream layer between UI and Supabase.
screens/     One folder per feature; each screen is a StatefulWidget/Consumer.
widgets/     Reusable, mostly stateless UI components.
utils/       Pure helpers (formatters, responsive, text).
main.dart    Bootstrap, routing table, deep-link wiring, deferred screen loading.
```

**Layering rule:** `screens` → `providers` → `services`/`repositories` → Supabase.
Widgets never call services directly except for trivial, self-contained actions.

## 3. App bootstrap & cold-boot path (DO NOT REGRESS)

`main()` is intentionally minimal so the first frame renders fast:

1. `WidgetsFlutterBinding.ensureInitialized()`.
2. `appInitialization = _initializeApp()` is assigned but **not awaited** in
   `main()`. The splash screen awaits it.
3. `runApp(const InstiyApp())` runs immediately.

`_initializeApp()` (the **critical path**, what the splash waits on):

- `SupabaseService.initialize()` — session restore (needed for auth gating).
- `HiveCacheService.initialize()` — opens the product cache box (offline-first
  home feed).

Everything else is deferred via `_initializeDeferred()` (fire-and-forget):

- Firebase + local notifications init.
- FCM listener setup.
- `SecretsService.instance.initialize()` — remote secret overrides.

### Rules for keeping cold boot fast

- **Never** add a blocking `await` to `_initializeApp()` that performs network
  I/O. Put it in `_initializeDeferred()` instead.
- `SecretsService` exposes safe local defaults, so secrets must stay deferred.
  Code paths that genuinely need fresh secrets (payments) call
  `SecretsService.instance.ensureLoaded()` on demand (see `PaystackService`).
- Rarely-used screens are **deferred imports** in `main.dart` (`deferred as ...`)
  and loaded via `_DeferredLoader`. Keep high-traffic screens eagerly imported.

## 4. Splash screen (two systems)

1. **Native splash** (shown before Flutter renders), generated by
   `flutter_native_splash` from `flutter_native_splash.yaml`:
   - Legacy (Android ≤ 11 / iOS): `assets/splash_logo.png` (768px canvas,
     ~512px logo, centered).
   - Android 12+: `assets/splash_logo_android12.png` (1152px canvas, 768px logo
     in the inner 2/3 safe zone so the circular OS mask does not crop it).
   - These source images are generated by `scratch/gen_splash.py` from
     `assets/logo.svg`. After changing the logo, re-run that script, then
     `dart run flutter_native_splash:create`.
2. **Flutter splash** (`lib/screens/splash/splash_screen.dart`): the animated
   route shown while `appInitialization` completes. Has a 600ms minimum display
   and an error/retry state.

> The historical "Android < 12 splash looks smaller" bug was caused by the
> Android 12 image lacking safe-zone padding (the OS mask shrank it). The fix is
> the padded `splash_logo_android12.png`. Do not point `android_12.image` back at
> a zero-padding asset.

## 5. Routing & deep links

- All routes are defined in `InstiyApp.onGenerateRoute` in `main.dart`.
- Transitions use `AppTheme.fadeSlideRoute`.
- Deep links (`app_links`) are handled by `NavigationService`:
  - Cold-start links are buffered in `NavigationService.pendingDeepLink` and
    consumed by the splash after its animation.
  - Foreground links are de-duplicated (`_handledLinks`) and suppressed during a
    3s post-resume grace period to ignore stale OEM Activity-recreation
    re-emissions.
- Supported schemes: `https://instiy.com/products/...` & `/store/...`, the custom
  `io.supabase.instiy://product|store/...`, and the share-product Worker URL.

## 6. Services conventions

- Services are classes with **static methods** and no instance state (except
  singletons like `SecretsService.instance`).
- Network calls go through either:
  - `SupabaseService.client` (Postgres / auth / realtime), or
  - `SupabaseService.callFunction(name, body:)` / `getFunction(name)` for
    Cloudflare Workers (30s timeout, attaches JWT + apikey).
- Always wrap I/O in try/catch, log with `debugPrint`, and fail gracefully.
  Never use `print` (lint-enforced).

---

## 7. State management

- Global providers are declared in `lib/providers/providers.dart` as
  `ChangeNotifierProvider`s.
- New, self-contained async state should prefer Riverpod code generation
  (`@riverpod` + `build_runner`), e.g. `home_products_riverpod.dart`.
- After editing any `@riverpod`-annotated file, run:
  `dart run build_runner build --delete-conflicting-outputs`.

---

## 8. Offline-first data

`ProductRepository.watchProducts()` is the template for cache-first data:

1. Emit cached data from Hive immediately (no shimmer on warm boot).
2. Fetch fresh data from Supabase.
3. Write back to Hive.
4. Emit fresh data.

Network failures are swallowed after the cache has been emitted so the UI stays
intact offline.

---

## 9. Notifications

- `LocalNotificationService` manages two Android channels: a normal channel (OS
  plays sound) and a silent channel (in-app `AudioPlayer` plays the sound).
- Background FCM messages are displayed by the OS; the Dart background handler
  must NOT show a local notification (avoids duplicates).
- Notification permission is requested **after** auth
  (`checkAndPromptFcmForAuthenticatedUser`), never on cold boot.

## 10. Android build

- `minSdk` / `targetSdk` / `compileSdk` follow the Flutter SDK defaults.
- Release builds enable R8 (`isMinifyEnabled`) and resource shrinking
  (`isShrinkResources`). Keep `android/app/proguard-rules.pro` updated when
  adding native-reflection-heavy plugins.
- Core library desugaring is enabled (required by
  `flutter_local_notifications`).

## 12. Conventions checklist (before committing)

- [ ] `flutter analyze` reports **0 errors**.
- [ ] No `print()` in `lib/` (use `debugPrint`).
- [ ] No blocking network `await` added to `_initializeApp()`.
- [ ] Secrets-dependent code calls `SecretsService.ensureLoaded()`.
- [ ] New rarely-used screens are deferred-imported in `main.dart`.
- [ ] `BuildContext` is not used across an `await` without a `mounted` check.
- [ ] Splash assets regenerated if the logo changed.

## 13. Design system — "Trust Purple" glassmorphism

Designed with the **UI/UX Pro Max** skill (Marketplace P2P palette +
Glassmorphism style). The goal: frosted glass that **pops** on a light, vibrant
canvas, with text colours deliberately off the background hue.

### Palette (all in `AppTheme`)

| Token            | Value       | Role                                  |
| ---------------- | ----------- | ------------------------------------- |
| `canvasWhite`    | `#FAF5FF`   | Pale lilac background (vibrant base)  |
| `accent`         | `#7C3AED`   | Trust purple (primary actions)        |
| `accentBright`   | `#9F67FF`   | Lighter purple for gradients/glow     |
| `successMoss`    | `#16A34A`   | Transaction green                     |
| `charcoalInk`    | `#3B0764`   | Deep-violet primary text (off-bg)     |
| `mutedSteel`     | `#6D5B8A`   | Muted violet-grey secondary text      |
| `whisperBorder`  | `#E9D5FF`   | Soft lilac border                     |

> **Contrast rule:** text is deep violet on a pale lilac canvas — never the same
> hue/lightness as the background. Do not introduce grey-on-grey text.

### Glassmorphism

Glass is **translucent** (white 18–35% alpha), not opaque, so the blur reads as
real glass. Use the shared helpers instead of hand-rolling blur:

- `AppTheme.frosted(child: ...)` — ClipRRect + BackdropFilter with blur **and**
  a `saturateMatrix` boost so the colourful base stays punchy through the glass.
- `AppTheme.glassDecoration()` — gradient surface + bright top light-source
  border + violet-tinted shadow for "pop-out" depth.
- `AppTheme.glassAppBar()` / `showGlassDialog()` — pre-built frosted app bar &
  dialog.
- `AppTheme.saturateMatrix` — reuse in any custom `BackdropFilter`.

Glass needs a colourful backdrop to pop: `ResponsiveLayout` paints
`AppTheme.ambientBackground` (lilac→violet→pink gradient + soft colour blobs)
behind every screen by default. Pass `ambientBackground: false` for screens that
must stay plain (e.g. full-screen media viewers).

This is **light-theme only** — do not switch the glass system to a dark theme.

### Dropdowns, selects & popup menus

All dropdowns are styled centrally so they match the glass theme and are easy to
tap on every screen size. **Do not restyle dropdowns per-screen** — change the
shared tokens/themes instead.

- **`ShadSelect` / `ShadPopover`** — styled via `lightTheme.selectTheme`,
  `popoverTheme`, and `optionTheme` in `AppTheme`. Frosted glass surface,
  saturated heavy blur, 18px radius, bright border, accent hover.
- **Material `PopupMenuButton`** — use `AppTheme.popupMenuTheme(isDark:)`
  (applied globally in `main.dart`'s `materialThemeBuilder`).
- **`DropdownButtonFormField`** — set `borderRadius: 18`, `dropdownColor`,
  `menuMaxHeight: 320`, and `itemHeight: AppTheme.minTapTarget`.

Touch-target rules (from UI/UX Pro Max UX guidelines):

- Each option is ≥ **48px** tall (`AppTheme.dropdownOptionPadding` h16/v14, and
  `AppTheme.minTapTarget = 48`).
- ≥ **8px** spacing around the options list (`AppTheme.dropdownListPadding`).
- Menus cap at `maxHeight: 320` and scroll; `minWidth: 180` keeps them readable
  while the framework constrains them to the viewport on small screens.
